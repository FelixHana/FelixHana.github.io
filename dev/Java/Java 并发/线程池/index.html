    线程池

    • 实现资源的复用，避免资源的重复创建和销毁带来的性能开销
    • 降低线程创建和销毁造成的消耗，提高响应速度，提高线程的可管理性

    ThreadPoolExecutor¶

    构造及关键属性¶

    构造参数¶

    • corePoolSize：用来工作的核心线程数量
    • maximumPoolSize：允许创建的最大线程数
    • keepAliveTime：超出 corePoolSize 后创建的线程存活时间或者是所有线程最大存活时间，取决于配置
    • unit：keepAliveTime 的时间单位
    • workQueue：任务队列，是一个阻塞队列，当线程数达到核心线程数后，会将任务存储在阻塞队列中
    • threadFactory ：创建线程所用的工厂
    • handler：拒绝策略，队列已满且线程数量达到最大线程数量，会调用该方法处理任务

    其他属性¶

    • AtomicInteger ctl 状态控制使用原子整型
      • 高 3 位状态，低 29 位工作线程
    • HashSet<Worker> workers 工作线程集合，修改需要获取全局锁

    状态¶


    RUNNING(-536870912) < SHUTDOWN(0) < STOP(536870912) < TIDYING(1073741824) < TERMINATED(1610612736)

    execute¶


    - 线程通过 submit() -> execute() 提交任务
    - 获取线程池状态后检查是否小于 corePoolSize
    - 小于则通过 addWorker() ThreadFactory 创建一个核心线程
    - 大于核心线程数则尝试入队
    - 双重检查状态若线程池停止，移除并拒绝任务
    - 如果工作线程为 0，增加一个空的非核心线程
    - 若队列满则尝试添加非核心线程，失败则拒绝任务

    addWorker¶

    更新线程池状态¶

    • 外层循环更新线程池状态
      • STOP 或 (SHUTDOWN + 传入任务不为空) 或 (SHUTDOWN + 任务队列为空)，说明无需添加新工作线程
      • 内层循环重新获取工作线程数
        • 判断核心线程数 / 非核心线程数超限
        • CAS 更新工作线程数，若成功跳出外层循环
        • CAS 失败重新判断线程池状态，这期间变为 SHUTDOWN+ 则跳到外层循环
          • 还是 RUNNING 则说明 CAS 失败由于并发问题，重复内层循环

    添加与启动 Worker¶

    • try 块 (Worker 构造 及 Thread.start() 异常需要调用 addWorkerFailed() 回退)
      • new Worker(firstTask) 实例，其中的线程工厂创建好线程对象
      • mainLock 全局上锁后进入 try 块（异常需要释放锁）
        • 确认线程池 RUNNING 或 (SHUTDOWN + 任务为 null) 否则工作线程添加失败
        • 确认 Worker 中的 Thread 可以启动
        • 添加到工作线程的 HashSet 中
        • 更新历史峰值容量
      • finally 全局解锁
      • 如果成功添加工作线程则 Thread.start() 启动线程
        • 这里 Worker 实现 Runnable 的 run() 方法，实际调用了 runWorker(this)
    • finally 处理工作线程启动失败的回退

    addWorkerFailed 处理¶

    • 全局上锁
      • 工作线程集合移除
      • 更新工作线程数
      • tryTerminate() 尝试终结线程池

    Worker 类¶


    - 继承 AQS (独占模式)，实现 Runnable
    - 构造时 setState(-1) 禁止线程在 runWorker() 之前中断
    - 通过 Worker 的加锁状态(tryLock())判断当前线程是否正在执行任务

    runWorker¶

    • 获取首个任务，解锁（AQS）允许中断
    • try 块保证工作线程后续处理
      • while 从队列中获取任务，Worker 加锁
        • 如果 STOP 线程池，中断工作线程，否则保证不中断
        • Runnable.run() 以及前后钩子方法，重新抛出异常
        • Worker 解锁，累计任务数量，清空 task
    • finally processWorkerExit() 处理线程退出

    getTask¶

    • 若 STOP 或 (SHUTDOWN + 任务队列空) 则工作线程 - 1 返回 null （结束线程）
    • 处理 RUNNING 下超出最大线程或超时的工作线程 CAS 自减
    • 从队列获取任务

    关闭线程池¶

    • 全局上锁后操作
    • shutdown() 修改状态 SHUTDOWN，尝试中断空闲线程 (Worker.tryLock() 即 AQS state>0 )，钩子函数，解锁
    • shutdownNow() 修改状态 STOP，立即中断所有线程，drainQueue() 清空队列并构建未执行列表，解锁

    最佳实践¶

    线程池参数¶

    • 最重要的参数
      • corePoolSize : 最小可以同时运行的线程数量
      • maximumPoolSize : 队列中的任务达到队列容量时，可以同时运行的线程数量为最大线程数
      • workQueue: 队列大小
    • 理论上通过区分 CPU 密集型与 I/O 密集型来确定参数
      • 查看 等待时间 / 计算时间的值
    • 实际上采用动态参数
      • 提供了 setter 方法用于动态调整

    其他¶

    • 使用ThreadPoolExecutor 的构造函数来声明，避免使用Executors 类（堆积请求导致 OOM），使用有界队列
    • 使用线程池提供的方法或 Actuator 进行监控
    • 不同业务使用分开的线程池
    • 实现 ThreadFactory 在线程池中创建线程时给线程命名
