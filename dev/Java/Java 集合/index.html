    集合

    集合类库用来持有对象，设计上分为两个概念
    - Collection 由单独元素组成的序列，符合特定的规则
    - List 插入顺序
    - Set 禁止重复
    - Queue 插入/输出的排队规则
    - Map 一组键值对象对，使用对象查找对象

    List¶

    • List 接口：支持添加、删除、查找等操作，并且可以通过下标进行访问

    ArrayList¶

    • 继承于 AbstractList ，实现 List, RandomAccess, Cloneable, Serializable 接口
    • 插入 / 删除元素（不考虑扩容）
      • 头部 O(n)
      • 尾部 O(1)
      • 指定位置：移动平均 2/n 个元素 O(n)
    • 底层Object [ ] 数组
    • 无参构造空数组，默认大小是 10
    • grow 方法中计算大约 1.5 倍的 newCapacity，判断与 minCapacity 的关系，返回目标扩容大小
    • 扩容使用Arrays.copyOf()复制所有元素

    ArrayList vs. Array¶

    • 长度灵活改变 / 指定大小
    • 泛型
    • ArrayList 只能存储对象（基本类型需要包装类）
    • 提供多种操作方法

    ArrayList vs. Vector¶

    • 主要实现 / 古老实现
    • 底层都使用 Object[]存储
    • 线程不安全 / 线程安全

    LinkedList¶

    • 继承于 AbstractSequentialList ，而 AbstractSequentialList 又继承于 AbstractList
      • 实现了List, Deque, Cloneable, Serializable 接口
    • 插入 / 删除元素
      • 头尾 O(1)
      • 指定位置：从头尾平均遍历 4/n 个元素 O(n)
    • 元素节点通过 Node<E> 定义，双向链表
    • node() 方法通过判断下标是否大于一半选择遍历方向，get() remove() add()中都用到 node()
    • unlink()方法，实现链表节点删除和节点置 null

    ArrayList vs. LinkedList¶

    • 都不是线程安全的
    • 底层数据结构
    • 插入删除性能
    • 支持随机访问与否
    • 内存空间使用

    Set¶

    • 与 Collection 有相同的接口，Set 就是行为不同的 Collection
    • 保证元素唯一
    • 添加的元素必须自定义equals() 保证唯一性

    HashSet¶

    • 继承于 AbstractSet ，实现 Set, Cloneable, Serializable 接口
    • 必须另外自定义hashCode(), 默认的 hashCode()会导致元素重复
    • 基于 HashMap 实现，元素实际由 key 保存，static final 空 Object 作为 value
    • 添加 / 判断存在 / 删除元素调用 Mapput() containsKey() remove() 方法

    TreeSet¶

    • 继承于 AbstractSet , 实现 NavigableSet, Cloneable, Serializable 接口
    • 基于 TreeMap 红黑树
    • SortedSet 意味着根据元素的比较方法排序, 添加的元素必须实现 Comparable 或传入Comparator

    LinkedHashSet¶

    • 继承于 HashSet , 实现 Set, Cloneable, Serializable 接口
    • 必须另外自定义hashCode(), 默认的 hashCode()会导致元素重复
    • 基于 HashSet 中的含参构造函数, 基于初始容量 16, 负载因子 0.75 的 LinkedHashMap
    • 与 HashSet 查找速度相同
    • LinkedHashMap内部使用链表维护元素插入顺序

    Map¶

    • 维护键-值关系
    • 保证键的唯一性
    • 任何键需要 equals() 方法, 若使用 Hash 则还需要实现合适的 hashCode(), 若使用有序 Map 还需要实现 Comparable或传入 Comparator

    HashMap¶

    • 继承于 AbstractMap , 实现 Map, Cloneable, Serializable 接口
    • 基于哈希表实现
    • 键值对插入/定位 O(1)
    • 构造器可以调整容量和负载因子
    • 底层数据结构
      • JDK 1.8 之前 底层使用数组+链表进行链地址法散列(拉链法)
      • JDK 1.8 之后 底层使用数组+链表 / 红黑树
    • hash() 方法将高/低 16 位异或增加随机性 且使得扩容后元素位于原索引 or 原索引+oldCapacity
    • (n - 1) & hash 取模 (n 为 2 整数次幂)

    • put 方法及扩容过程

      • table 未初始化先进行初始化
      • 使用 hash 出的结果, 判断tab[i = (n - 1) & hash]是否存在元素
        • table[i]是空的则直接插入
        • 若当前位置有元素
          • key 相同则直接覆盖
          • 若是 TreeNode 则 putTreeVal() 插入红黑树节点
          • 都不是则遍历当前位置的链表
            • 链表中找到 key 相等的直接覆盖
            • 遍历到尾部没有相等的 key 则尾插节点, 若当前链表 >= TREEIFY_THRESHOLD - 1 调用 treeifyBin() 进行扩容或将链表变为红黑树
      • 添加成功后检查 table 是否需要扩容

    • 链表大于等于 TREEIFY_THRESHOLD - 1调用 treeifyBin

      • 若 table 数组大小小于 MIN_TREEIFY_CAPACITY 即 64, 则选择扩容 table
    • resize() 方法会触发 split() 将红黑树分割
      • 若分割后的树节点 <= UNTREEIFY_THRESHOLD 则变为链表

    HashMap vs. HashTable¶

    • Hashtable 直接在方法上加 synchronized 关键字, 不是高并发实现

    HashMap vs. TreeMap¶

    • 基于数组+链表+红黑树 / 基于红黑树\
    • 通过 hash 查找 无冲突情况 O(1) / 通过红黑树保证有序 O(logN)

    TreeMap¶

    • 继承于 AbstractMap , 实现 NavigableMap, Cloneable, Serializable 接口
    • 基于红黑树实现, 键或键值对通过实现 Comparable 或传入 Comparator 确定顺序
    • 先尝试用 Comparator 的compare()进行比较，若不存在则使用 Comparable 的compareTo()进行比较
    • 需要逆序则构造传入Comparator.reverseOrder()

    LinkedHashMap¶

    • 继承于 HashMap , 实现 Map接口
    • 基于 HashMap 的实现, 除遍历外性能稍低
    • 使用子类定义的 Entry 节点维护一个双向链表, 增加了遍历的性能
    • 构造时可以通过 accessOrder 选择按访问顺序(LRU) 遍历还是插入顺序遍历
    • HashMap中定义了 afterNodeAccess afterNodeInsertion afterNodeRemoval. LinkedHashMap 中进行了重写override, 节点操作后调用, 用于维护链表
    • 重写了 HashMap 中的某些方法如 get()

    Queue¶

    • 单端队列 通常为 FIFO 的

    ArrayDeque¶

    • 继承于 AbstractCollection , 实现 Deque, Cloneable, Serializable 接口
    • 基于循环数组实现: 底层是数组+头尾指针
    • 初始大小为 16, 每次扩容翻倍
    • 不允许放入 null 元素
    • 向 head 端插入元素使用 head = (head - 1) & (elements.length - 1) 计算下标 (数组为 2 的整数次幂)
    • tail 指向下一个空位 (tail + 1) & (elements.length - 1) == head 是判满条件

    ArrayDeque vs. LinkedList¶

    • LinkedList 也实现了 Deque 接口
    • 变长数组+双指针 / 链表
    • 不支持 / 支持 null 数据
    • 适合随机访问 / 适合顺序访问
    • 插入性能: ArrayDeque 扩容操作均摊后仍高于需要每次分配堆空间的 LinkedList

    PriorityQueue¶

    • 继承于 AbstractQueue , 实现Serializable 接口
    • 基于优先级堆实现的优先队列
    • 维护顺序需要实现 Comparable 或传入 Comparator
    • 插入的复杂度 O(logN) 涉及到维护堆的性质
    • grow() 扩容: 容量小于 64 则翻倍, 否则增长 50%

    Iterable & Iterator¶

    • Iterable 表示实现这个接口的类支持迭代器访问
      • iterator() 方法返回一个迭代器对象
    • Iterator 提供遍历集合的具体功能，以便逐一访问元素
      • hasNext()、next() 和 remove() 等方法，用来控制集合的遍历过程

    Iterable 接口中 forEach 方法接受一个 Consumer 对象作为参数，用于对集合中的每个元素执行指定的操作。该方法使用 for-each 循环遍历集合中的元素，对于每个元素，调用 Consumer 对象的 accept 方法执行指定的操作.
    for-each 语法糖背后仍然是利用 Iterator 接口的方法进行遍历
    - 实现了 Iterable 的集合会重写 iterator() 方法，使用内部类实现了 Iterator 接口及相关控制方法
    - 使用内部类可以支持多种遍历方式，如 LinkedList 的 DescendingIterator
    - Map 通过 map.entrySet()、map.keySet()、map.values() 返回 Collection 的方式使用 for-each 迭代

    Comparable & Comparator¶

    • 一个类实现了 Comparable 接口，意味着该类的对象可以直接进行比较（排序），但比较（排序）的方式只有一种
    • 一个类如果想要保持原样，又需要进行不同方式的比较（排序），就可以定制比较器（实现 Comparator 接口）

    Fail-fast & Fail-safe¶

    • Fail-fast 是一种通用的系统设计思想，一旦检测到可能会发生错误，就抛出异常，程序将不再往下执行
    • java.util 下的集合类都是 fail-fast 的
    • 集合中的 for-each 操作
      • 使用 for-each 循环里对元素进行 remove/add 操作会报错
      • 迭代器在遍历集合时会维护一个 expectedModCount 属性来记录集合被修改的次数
      • foreach 循环中执行删除操作会导致 expectedModCount 属性值与实际的 modCount 属性值不一致
      • 解决方法：
        • 普通的 for 循环
        • 使用迭代器的 remove() 方法来删除元素
        • Collection 提供的 removeIf()
        • 使用 fail-safe 的集合
